# Perfboard Placer — Лог проекта

## Цель
Построить интерактивный инструмент на Tkinter, который размещает реальные Fritzing SVG-компоненты на макетной плате 70×90 мм, корректно отрисовывает их и позволяет перетаскивать с привязкой к сетке отверстий.

## Ключевые решения
- **Tkinter Canvas** вместо чистого SVG: с самого начала даёт интерактивный зум/пан/перетаскивание.
- **Команды отрисовки хранятся как есть** (в SVG-единицах), `mm_per_unit` применяется при рендеринге — парсер остаётся универсальным, а рендеринг корректным для любой системы единиц SVG (мм или милы).
- **Левый медный круг как точка привязки** — все варианты TO-92/DO-41/аксиальные имеют единый левый вывод; привязка к целевому отверстию `(col, row)`, а не автоматическое вычисление от положения вывода.
- **Поточечное отсечение удалено** после исправления дуг — дуги больше не выходят за viewBox, отсечение не нужно.
- **Rect на медном слое пропускается** — артефакт редактора Fritzing (DO-41 300mil SVG имел rect + circle, полностью совпадающие).

## Архитектура

### `board.py` — Модель платы
- 70×90 мм макетная плата, 26 колонок × 31 строка, шаг 2.54 мм
- Отверстие (0,0) на расстоянии (3.25 мм, 6.90 мм) от верхнего левого угла платы
- `hole_pos(col, row)` → координаты в мм
- `margin_x()`, `margin_y()` вычисляют левый/верхний отступ

### `pcb_library.py` — Парсер SVG
- Читает Fritzing PCB SVG → `Package` с объектами `DrawCommand`
- Обрабатывает: circle, rect, line, path (M/L/C/S/A/Z)
- Безье (C/S) → 16 отрезков; дуги (A) → 24 отрезка
- **Исправление дуг (строка 73):** `s = 1 if large != sweep else -1` (инвертированное условие). Сегменты дуг теперь остаются внутри viewBox.
- Разбор слоёв из `<g id="copper0/1">`, `<g id="silkscreen">`
- Определение `mm_per_unit`: `width_mm / vb_w`. SVG могут быть в мм (mm_per_unit=1) или милах (0.0254)
- `_tk_color()` преобразует `rgb(R,G,B)` → `#rrggbb` для Tkinter

### `perfboard_placer.py` — Главное приложение
- Класс `App`: корень Tkinter, загружает SVG, размещает при старте, обрабатывает перетаскивание
- `PerfboardCanvas`: отрисовывает плату (отверстия) и компоненты на canvas с прокруткой/зумом
- **Отрисовка компонентов:** `_draw_command` диспетчеризует по типу, преобразует SVG → мм → пиксели canvas

### Перетаскивание
- Теги `comp_*` на всех элементах компонента
- `<Motion>` → курсор `hand2` над компонентами
- `<Button-1>` начало, `<B1-Motion>` привязка левого вывода → ближайшее отверстие, `<ButtonRelease-1>` конец

### Поворот и отражение (клавиши)
- `r` — повернуть на 90° CW вокруг левого вывода
- `h` — отразить по горизонтали
- `v` — отразить по вертикали
- Трансформация применяется в `_draw_command` через `_transform_point`: `dx = px - ref`, flip H/V, затем поворот

### Выделение
- Клик по компоненту → жёлтая пунктирная рамка, хоткеи применяются к нему
- Клик в пустоту → снятие выделения
- `Delete` / `Backspace` — удалить выделенный компонент

### Меню («Файл», «Компонент»)
- Верхнее меню вместо боковой панели
- «Файл»: Открыть / Сохранить / Сохранить как… / Выход
- «Компонент»: список всех загруженных компонентов
- При выборе компонента из меню — полная копия следует за курсором (snap к сетке)
- ЛКМ фиксирует размещение, `Esc` отменяет

### Сохранение / Открытие (.brd)
- Формат JSON с расширением `.brd`
- Сериализуются все размещения (файл SVG, позиция, поворот, отражение) и маршруты
- Флаг `_dirty` отслеживает изменения: диалог «Сохранить изменения?» при закрытии/открытии

### Режим трассировки (`N`)
- `N` — включить/выключить
- Белое перекрестие (dash-dot) следует за курсором с привязкой к отверстиям
- Первый клик — установка начальной точки
- Движение мыши — preview L-линии (H→V) от последней точки к курсору
- Второй клик — фиксация сегмента, новая точка становится началом следующего
- `Esc` — отмена текущего сегмента и выход из режима
- **Выбор сегмента:** ЛКМ по линии маршрута выделяет его (жёлтая линия 10px)
- **Удаление сегмента:** `Delete` / `Backspace` удаляет выделенный маршрут

### Внешний вид (текущий)
- Цвет платы: `#2b4a2b`
- Отверстия: чёрный центр `#222222`, золотая оконтовка `#c9a84c` (width 3px), радиус `0.5 × scale`
- Пэды компонентов: оранжевые `#e87a20` (SVG stroke игнорируется на copper-слое)
- Шелкография: `#f0f0f0` (SVG stroke игнорируется, в т.ч. `black` у TO-220)
- Маршруты (сегменты): оранжевые `#e87a20` (как пэды), ширина 6px
- Выделенный маршрут: жёлтый `#ffff00`, ширина 8px
- Перекрестие: белое `#ffffff`, dash `(8,3,2,3)`

## Исправленные баги
1. **Формула дуги** (`pcb_library.py:73`): `s = 1 if large != sweep else -1` — была инвертирована, дуги выглядели как крылья бабочки
2. **Овальные отверстия** (`perfboard_placer.py`): округление координат до целых через `round()` устранило овальный рендеринг
3. **Несоответствие единиц при перетаскивании** (`perfboard_placer.py:_drag_move`): `sx` был в SVG-единицах, `mm_x` в мм — добавлено `* mmu`
4. **Перекрытие rect на меди** (`perfboard_placer.py:_draw_command`): rect на медном слое пропускается, чтобы показать реальные круглые контактные площадки
5. **Цвет пэдов не менялся** (`perfboard_placer.py:_draw_command`): SVG stroke переопределял PAD_COLOR — добавлено `stroke = ""` для copper-слоя
